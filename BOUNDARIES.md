# BOUNDARIES

Quote-backed refusals and hard avoids only. First-pass coverage is **thin** on explicit “I refuse X” language; these are the clearest public lines.

## Product / AI shape
- **Not another notes app. Not another chatbot.** Prefer systems that remember and follow through. (Slime LinkedIn, 2026-03)
- Don’t ship assistants that only add **one more response to manage** — aim for fewer mental tabs and real actions. (X 2026-03)
- Don’t call something an agent if every run is a chat nag: that’s a **nagger with a cron job**. (X reply 2026-03)

## Startup / validation
- **A waitlist is NOT validation. Credit cards are.** Don’t treat interest lists as proof. (Failed-startup LinkedIn, 2026-01)
- **Don’t build MVPs before knowing if anyone cares.** Validate fast and cheap first. (X 2026-03)
- Don’t stay in the **builder trap** of “one more feature and it’ll click.” (LinkedIn 2026-01)

## Engineering bar
- Don’t call vibecode **production** without concurrency test, idempotency key, rollback path, and a synthetic monitor. (X reply 2026-03)
- Don’t skip **confidence gates** before side effects (e.g. sending email on low retrieval score). (X reply)
- Don’t rely on **views alone** as video quality signal. (Shorta LinkedIn)
